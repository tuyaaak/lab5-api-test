## 2. API-ийн анхны шалгалт

`server.js` файлыг Node.js ашиглан ажиллуулсан.

`PUT /students` хүсэлтээр оюутан, `PUT /courses` хүсэлтээр хичээл үүсгэсэн. Дараа нь `POST /registrations` хүсэлтээр бүртгэл хийж шалгасан.

Амжилттай бүртгэлд дараах хариу ирсэн.

```json
{
  "result": "OK",
  "registrationID": 1
}
```

`registrationID` нь сервер ажиллах хугацаанд нэмэгддэг тул тестээр яг нэг тодорхой тоо гэж шалгаагүй.

## 3. Сонголт ба төлөөлөх утгууд

| Сонголт | Хүчинтэй утга | Алдааны болон хязгаарын утга |
|---|---|---|
| studentID | Байгаа оюутан | Байхгүй, талбар дутуу |
| Оюутны төлөв | active | inactive |
| coursesTaken | Урьдач хичээл үзсэн | Үзээгүй, хоосон массив |
| courseID | Байгаа хичээл | Байхгүй, талбар дутуу |
| prerequisites | Урьдач нөхцөл хангасан | Дутуу, хоосон массив |
| JSON body | Зөв JSON | Буруу JSON |
| Давхар алдаа | Нэг алдаа | Идэвхгүй оюутан болон байхгүй хичээл |

## 4. Тестийн спецификаци

| ID | Тестийн нөхцөл | HTTP | Expected result |
|---|---|---|---|
| T01 | Амжилттай бүртгэл | 201 | OK |
| T02 | Оюутан байхгүй | 200 | ERROR_NO_STUDENT |
| T03 | Оюутан идэвхгүй | 200 | ERROR_INACTIVE_STUDENT |
| T04 | Хичээл байхгүй | 200 | ERROR_NO_COURSE |
| T05 | Урьдчилсан хичээл дутуу | 200 | ERROR_PREREQUISITES |
| T06 | studentID талбар байхгүй | 400 | ERROR_BAD_REQUEST |
| T07 | courseID талбар байхгүй | 400 | ERROR_BAD_REQUEST |
| T08 | Хоёр ID хоёулаа байхгүй | 400 | ERROR_BAD_REQUEST |
| T09 | Оюутан идэвхгүй, хичээл байхгүй | 200 | ERROR_INACTIVE_STUDENT |
| T10 | JSON формат буруу | 400 | ERROR_BAD_JSON |

Нийт 10 тестийн нөхцөл тодорхойлсон.

Тест бүр шаардлагатай setup хүсэлттэй бөгөөд тусдаа оюутан болон хичээлийн код ашигласан.

HTTP статус болон `result` талбарыг `pm.test` ашиглан шалгасан. Амжилттай бүртгэлд `registrationID` тоон утга мөн эсэхийг нэмэлтээр шалгасан.

## 6. Newman FAIL туршилт

Нэг HTTP статусын хүлээгдэх утгыг зориуд буруу болгосон.

Амжилттай бүртгэлд сервер `201` буцаасан боловч тест `200` гэж хүлээсэн.

Команд:

```bash
newman run lab05-collection-fail.json
```

| Хэмжүүр | Executed | Failed |
|---|---:|---:|
| Iterations | 1 | 0 |
| Requests | 23 | 0 |
| Test scripts | 23 | 0 |
| Prerequest scripts | 0 | 0 |
| Assertions | 48 | 1 |

Алдааны мэдээлэл:

```text
AssertionError: HTTP status 200 (зориуд буруу)
expected response to have status code 200 but got 201
```

- Алдаа гарсан тест: T01 — Амжилттай бүртгэл
- Assertions failed: 1
- Exit code: 1 

Сервер зөв ажиллаж байсан ч тестийн хүлээгдэх утга буруу байсан учраас assertion унасан.

Үр дүн: `results/newman-fail.txt`

## 7. Newman DOWN туршилт

Серверийг `Ctrl + C` дарж унтраасны дараа үндсэн collection-ийг дахин ажиллуулсан.

Команд:

```bash
newman run lab05-collection.json
```

Гарсан алдаа:

```text
connect ECONNREFUSED 127.0.0.1:3000
```

Энэ удаа сервер ажиллаагүй учраас API хүсэлтүүд холбогдож чадаагүй.

FAIL туршилтад серверийн хариу болон тестийн хүлээлт зөрсөн. DOWN туршилтад холболт тогтоож чадаагүй тул серверийн хариуг шалгах боломжгүй болсон.

Exit code: 1

Үр дүн: `results/newman-down.txt`

## 8. Дүгнэлт

Энэ лабораторид хичээлд бүртгүүлэх API-г тестэлсэн. Эхлээд тестлэх функцээ сонгож, оролтын сонголтуудыг тодорхойлсон. Дараа нь сонголт бүрийн төлөөлөх утгуудыг ялгасан. Хамгийн их бодол шаардсан хэсэг нь хэд хэдэн алдаа давхцах үед ямар үр дүн буцахыг тодорхойлох байв. Жишээлбэл, идэвхгүй оюутан байхгүй хичээлд бүртгүүлэхэд идэвхгүй оюутны алдаа түрүүлж шалгагддаг. Оролтын талбар дутуу байхыг бизнес логикийн алдаанаас тусад нь шалгасан. Тест бүр өөрийн setup-тай байх нь өмнөх тестийн өгөгдлөөс хамаарахгүй ажиллахад хэрэгтэй байсан. Newman ашиглан 23 хүсэлт, 48 assertion ажиллуулж үр дүнг текст файлд хадгалсан. FAIL туршилтаар буруу assertion, DOWN туршилтаар холболтын алдааг ялгаж үзсэн. Ингэснээр зөвхөн API-ийн хариуг бус, тестийн хүлээлт болон орчны ажиллагааг хамтад нь шалгах шаардлагатайг ойлгосон.
